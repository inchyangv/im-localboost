# 데모 대본 (전체 흐름, 약 8분)

시민 한 명(본인 지갑), 가맹점 한 곳, 대구시, 은행이 등장해서 예산 예치부터 원화 정산까지 한 바퀴를 돕니다. 지갑 없이 3분 안에 보는 경로는 [README](../README.md#3분-둘러보기-지갑-없이)에 있습니다.

## 준비

이 대본은 시드 직후 상태(북성로 예산 0원, 오늘 결제 없음)를 전제합니다. 하루 경계는 KST입니다. 같은 KST 날에 이미 데모를 돌렸다면 아래 순서로 새 시드를 만드세요.

```
make deploy-kairos                       # 컨트랙트 재배포 + 시드, shared/ 갱신
railway up --service engine --ci         # 새 주소로 엔진 재배포
make deploy-web ENGINE_URL=https://engine-production-1edd.up.railway.app ENV_FILE=.env.kairos
```

시민 역할을 할 브라우저에는 Kaia Wallet 또는 MetaMask를 설치해 둡니다. 관리자 도구는 상단에서 데모 계정을 고르면 되므로 지갑이 필요 없습니다.

## 진행할 때 알아 둘 점

- **10단계는 보류가 아니라 차단으로 나옵니다.** 시드 직후에는 지갑이 전부 신규여서, 환류 규칙은 tier 1이지만 모델이 0.947~0.989를 주어 최종 등급이 tier 2가 됩니다(최종 등급은 규칙과 모델 중 높은 값). 보류(tier 1) → 환수 경로만 따로 보려면 로컬에서 등급을 지정해 결제를 만듭니다.

  ```
  cd contracts && PAYER=2 MERCHANT=1 AMOUNT=10000 TIER=1 npx hardhat run scripts/demo-pay.ts --network localhost
  ```

- **11단계는 항상 `NonceUsed`를 보여 줍니다.** 컨트랙트는 만료를 nonce보다 먼저 검사하므로, 보관된 서명의 남은 유효 시간이 30초 미만이면 버튼이 새 결제를 먼저 만들고 그 서명을 다시 제출합니다.
- **정시 직후 45초 동안은 결제 버튼이 카운트다운을 보여 줍니다.** 위험 모델이 율 변경 직후의 결제에 민감하기 때문입니다(`secs_since_rate_change`). 정시를 걸쳐서 시연하지 않는 편이 좋습니다.
- **Kairos에서는 보류 지연 60초가 실제 시간입니다.** 공개 RPC여서 트랜잭션 확인에도 몇 초씩 걸립니다.
- **QR 완료 판정은 금액으로 합니다.** 참조값은 온체인에 없으므로, 가맹점 화면은 QR을 만든 뒤에 들어온 같은 금액의 `Paid`를 완료로 봅니다. 시연 중에는 같은 가게에 같은 금액을 동시에 결제하지 마세요.

## 브라우저 없이 검증하기

```
cd web && npx tsx --env-file=.env.local scripts/demo-e2e.ts       # 예치 → 결제 → 재결제 → 담합 링 → 서명 재사용 (데모 계정, 로컬)
cd web && npx tsx --env-file=.env.local scripts/verify-wallet.ts  # 일회용 키로 지갑 온보딩 → approve → 결제
make test-integration                                             # 엔진 서명 → 온체인 결제 → 재사용 revert
```

`demo-e2e.ts`와 `make test-integration`은 각각 새 시드에서 시작해야 합니다. 둘 다 "오늘 결제 없음"을 전제하기 때문입니다.
