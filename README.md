# iM-LocalBoost

상권·시간대별로 보너스율이 달라지는 지역화폐 결제 프로토타입입니다. 소비자가 가맹점에 mock iMKRW로 결제하면 컨트랙트가 온체인에 게시된 보너스율로 보너스 크레딧을 계산해 지급하고, 오프체인 엔진이 수요 예측으로 율을 정하고 담합 위험 등급을 EIP-712 서명으로 발급합니다.

## 시작하기

```
make setup
```

`contracts/`, `web/`의 npm 의존성과 `engine/`, `sim/`이 함께 쓰는 루트 `.venv`(Python 3.11)를 설치하고, `.env.example`을 `.env`로 복사합니다. 로컬 개발은 Hardhat 기본 계정을 사용합니다.

## 데모 순서 (로컬)

사전 준비: `make node` → `make deploy-local` → `make train` → `make engine` → `make web`. 웹은 `.env`의 `WEB_ORIGIN` 포트(기본 3000)로 뜨고, 상단의 페르소나 전환기로 계정을 고릅니다. 브라우저 지갑 확장은 쓰지 않으며, 페르소나 키는 **데모 전용**으로 브라우저 번들에 들어갑니다.

| 단계 | 페르소나 | 화면 | 하는 일 | 기대 결과 |
| --- | --- | --- | --- | --- |
| 1 | 대구시 | `/city` | 북성로에 예산 예치(예: 500,000원) → "율 게시"(데모 전용: 북성로 10% 고정 체크) | 북성로 카드와 `/` 약도에 10.0% 표시 |
| 2 | 소비자 1 | `/` | 북성로 한식당에 10,000원 결제 | 결과 카드 "지급", 보너스 1,000원, 크레딧 1,000원, 가맹점 +10,000원 |
| 3 | 소비자 1 | `/` | 같은 가게에 다시 결제 | 성공, 보너스 0원, 사유 "오늘 이미 보너스를 받은 가게" (미리보기와 결과 카드 모두) |
| 4 | 대구시 → 은행 | `/city` | "담합 링 실행" | 위험 로그에 tier ≥ 1과 "환류"가 3건 이상. tier 1 건은 보류 목록에 생기고 은행 페르소나로 "환수"하면 예산이 복원됨. tier 2 건은 보너스 0원으로 즉시 차단 |
| 5 | 대구시 | `/city` | "서명 재사용 공격" | "이미 사용된 서명입니다 (재사용 차단)"과 에러 이름 `NonceUsed` |
| 6 | 대구시 | `/city` | 하단 "시뮬레이션" 섹션 | `make sim` 결과 차트 (결과 파일이 없으면 안내 문구) |

### 알아 둘 점

- 최종 위험 등급은 규칙과 모델 중 큰 값입니다. 학습된 모델은 "생성 직후 지갑 + 가맹점→지갑 환류 + 직후 결제"를 0.9 이상으로 평가하므로, 4단계의 담합 링(소비자 2~5)은 규칙 tier 1(환류)에 모델이 더해져 **tier 2(보너스 0원, 보류 없음)** 로 판정되는 것이 기본입니다. 소비자 5는 "신규 지갑 군집" 규칙만으로도 tier 2입니다. 방어가 더 강하게 작동한 결과이며 수치를 조정하지 않았습니다.
- 보류(tier 1) → 지급/환수 흐름을 따로 보려면 attester 키로 직접 tier 1 서명을 만들어 결제하는 검증 스크립트를 쓰세요: `cd contracts && PAYER=2 MERCHANT=1 AMOUNT=10000 TIER=1 npx hardhat run scripts/demo-pay.ts --network localhost`. 이후 `/city` 보류 목록에서 은행 페르소나로 "환수"를 누르면 상권 예산이 복원됩니다.
- 브라우저 없이 같은 순서를 검증하려면: `cd web && npx tsx --env-file=.env.local scripts/demo-e2e.ts`.
